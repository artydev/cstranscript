TranscriptAudio : Guide de Fonctionnement et Déploiement IIS

Architecture .NET 8/9 • Intégration API Albert (Souveraine) • Streaming SSE

1. Présentation du Système

TranscriptAudio est une solution de transcription automatisée optimisée pour les besoins de l'administration. Elle permet de transformer des fichiers audio (MP3, WAV, WebM) en texte via l'intelligence artificielle Albert (v3) fournie par la DINUM (Etalab).

L'application est conçue pour supporter des fichiers allant jusqu'à 100 Mo tout en offrant un retour visuel en temps réel grâce au protocole Server-Sent Events (SSE).

2. Architecture Logique

Le programme repose sur trois piliers technologiques :

  • Minimal API (.NET 8/9) : Pour une gestion performante des flux d'upload et des connexions persistantes.
  • HTMX : Pour une interface réactive miminimisant drastiquement l'utilisation de Javascript.
  • Background Worker : Un service singleton qui gère une file d'attente (Bounded Channel) pour ne pas saturer l'API distante.

3. Configuration Spécifique pour IIS

Lors d'un déploiement sur IIS, les limitations par défaut du serveur web Windows peuvent bloquer les fichiers de plus de 30 Mo. Les modifications suivantes sont impératives :

Configuration du fichier web.config

Ce fichier doit être placé à la racine du site pour autoriser les uploads de 100 Mo et désactiver le buffering SSE :

<configuration>
  <system.webServer>
    <security>
      <requestFiltering>
        <!-- MaxAllowedContentLength en octets (105 Mo ici) -->
        <requestLimits maxAllowedContentLength="110100480" />
      </requestFiltering>
    </security>
    <aspNetCore processPath="dotnet" arguments=".\TranscriptAudio.Presentation.JSChunk.dll" 
                stdoutLogEnabled="false" hostingModel="inprocess">
      <handlerSettings>
        <!-- Désactiver le buffering IIS pour permettre le streaming temps réel (SSE) -->
        <handlerSetting name="responseBufferLimit" value="0" />
      </handlerSettings>
    </aspNetCore>
  </system.webServer>
</configuration>
Pool d'application : Le pool d'application IIS doit avoir les droits d'écriture sur le dossier temporaire de Windows (C:\Windows\Temp) car le programme utilise le disque pour streamer les fichiers volumineux sans saturer la RAM.

4. Cycle de Traitement des Données

4.1 Phase d'Upload (Streaming Disque)

Pour éviter les pics de mémoire RAM (Out Of Memory), le programme n'utilise pas de MemoryStream. Le flux est lu directement depuis la requête HTTP et écrit dans un fichier temporaire via FileOptions.DeleteOnClose. Le fichier est automatiquement supprimé dès que le service de transcription a fini sa lecture.

4.2 Communication SSE (Server-Sent Events)

Une fois l'upload terminé, le client ouvre une connexion GET persistante. Le serveur envoie des fragments HTML au format SSE : 

data: <div class="status">Transcription en cours...</div>\n\n

Note importante : IIS peut tenter de bufferiser ces messages. La configuration responseBufferLimit="0" dans le web.config est cruciale pour que l'utilisateur voie la progression en temps réel.

5. Détails des Endpoints

Route Méthode Description
/transcribe-audio POST Réception du fichier audio et mise en file d'attente.
/transcribe-sse/{id} GET Flux de données temps réel pour les mises à jour de statut.
/transcript - PathBase configuré pour IIS si l'application est dans un sous-répertoire.

6. Optimisation de l'IA (Albert API)

Le service WhisperService intègre des mécanismes de résilience :

  • Polly Retry Policy : En cas d'erreur 429 (Too Many Requests), le système attend et réessaie automatiquement 3 fois.
  • Multi-threading : Jusqu'à 3-5 ouvriers simultanés (configurable) traitent la file d'attente.
  • Formatage : Le texte est renvoyé avec white-space: pre-wrap pour respecter la ponctuation générée par l'IA.

7. Maintenance et Logs

En cas de déploiement IIS, les erreurs critiques peuvent être consultées dans l'Observateur d'événements Windows (Journaux Windows > Application). Il est recommandé d'activer les logs stdout dans le web.config uniquement lors des phases de diagnostic.
